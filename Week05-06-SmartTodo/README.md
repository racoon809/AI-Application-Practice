# 5~6주차 · 스마트 할 일 관리 앱 (`Week05-06-SmartTodo`)

> 제출자 서승하 (243441) · 컴퓨터공학과 3학년 · GitHub [racoon809](https://github.com/racoon809) · 제출일 2026-10-28 · [전체 목차](../README.md)

매일 할 일을 기록하고 **업무 / 개인 / 공부** 카테고리로 관리하는 웹 앱입니다.
[4주차 앱](../Week04-TodoApp/)을 바탕으로 5주차에 키워드 기반 자동 분류를, 6주차에 데스크톱 화면용 레이아웃을 더했습니다. 두 화면은 공통 로직 `core.js`를 함께 쓰고, 화면마다 다른 부분만 각 폴더의 `ui.js`에 있습니다.

## 바로 실행하기

| 버전 | 파일 | 추천 화면 |
|---|---|---|
| 5주차 자동 분류 | [`week05/index.html`](week05/index.html) | 모바일·좁은 창 |
| 6주차 데스크톱 레이아웃 | [`week06/index.html`](week06/index.html) | 1280px 이상 넓은 화면 |

GitHub Pages: [5주차](https://racoon809.github.io/AI-Application-Practice/Week05-06-SmartTodo/week05/) · [6주차](https://racoon809.github.io/AI-Application-Practice/Week05-06-SmartTodo/week06/)

1. 파일을 더블 클릭하면 기본 브라우저(Chrome·Edge 권장)에서 열립니다.
2. 설치·서버·인터넷 연결이 필요 없습니다. (글꼴만 인터넷에서 불러오며, 오프라인이면 기본 글꼴로 표시)
3. 처음 열면 예시 할 일 4개가 들어 있습니다. 5주차와 6주차 화면은 같은 저장 키를 쓰므로 한쪽에서 추가한 할 일이 다른 쪽에도 보입니다.
4. 할 일은 브라우저 `localStorage`에 저장되어 새로고침해도 유지됩니다. 서버가 없으므로 다른 사용자·브라우저와 데이터가 섞이지 않습니다.

### 자동 카테고리 분류는 이렇게 동작합니다
할 일 문장에 들어 있는 단어를 카테고리별 키워드 사전과 비교해 점수를 매기고, 가장 높은 카테고리를 추천합니다. 동점이면 추천하지 않고 사용자가 고른 카테고리로 저장합니다.

| 카테고리 | 키워드 예시 |
|---|---|
| 업무 | 회의, 미팅, 보고서, 개발, 배포, 회사, 출근, 프로젝트, 메일, 스케줄 |
| 개인 | 집, 운동, 헬스, 산책, 장보기, 청소, 영화, 친구, 가족, 병원 |
| 공부 | 공부, 시험, 과제, 강의, 수업, 복습, 독서, 토익, 자격증, 레포트 |

직접 확인해 보기
| 입력 | 선택 | 결과 |
|---|---|---|
| 내일 회사 스케줄 확인 | 개인 | 업무 추천 창 (키워드: 회사, 스케줄) |
| 영화 보러 가기 | 업무 | 개인 추천 창 (키워드: 영화) |
| 중간고사 공부 | 개인 | 공부 추천 창 |
| 우유 사기 | 개인 | 일치 키워드 없음 → 개인 그대로 저장 |

코드 위치: [`core.js`](core.js)의 `[5주차]` 블록 — `DEFAULT_KEYWORDS`, `analyzeText()`, `resolveCategory()`, `findReclassifyCandidates()`

### 공통 로직과 화면별 코드 나누기
처음에는 6주차 `web_version/script.js`가 5주차 `script.js`를 그대로 복사한 파일이었습니다(바이트 단위 동일). 한쪽만 고치면 두 화면이 달라지는 문제가 있어 다음처럼 나눴습니다.

| 파일 | 하는 일 |
|---|---|
| `core.js` | 두 화면이 똑같이 쓰는 모든 로직. 렌더링할 때 화면별 훅 `renderOverall(pct)`, `renderFilterTitle(filter)`를 호출 |
| `week05/ui.js` | `window.TodoLayout`에 훅 등록 — 진행률을 가로 막대(`#overallBar`)로 표시 |
| `week06/ui.js` | 진행률을 사이드바 링(`#overallRing`)으로, 현재 필터 이름을 목록 제목(`#listTitle`)으로 표시 |

화면에 없는 요소는 `core.js`가 확인한 뒤 건너뛰므로 두 HTML이 같은 로직을 안전하게 공유합니다.

## 실습 기록

### 4주차 · 단계별 프롬프트로 기본 앱 제작
결과물: [`Week04-TodoApp/`](../Week04-TodoApp/) — 카테고리·우선순위, 진행률 대시보드, 더블 클릭 수정, 드래그 정렬, 다크 모드, 실행 취소 토스트, JSON 내보내기/가져오기

claude.ai에서 PRD를 만들고 아래 프롬프트로 5단계로 나눈 뒤, Claude Code에서 순서대로 실행했습니다.
```
이 PRD를 클로드 코드에서 사용할 단계별 프롬프트로 변환해 줘. 5개의 핵심 단계로 정리해서 각 단계마다 명확한 지시 사항을 만들어 줘.
```
1. 기본 구조 및 핵심 기능 (추가·완료·삭제)
2. 카테고리 기능 및 UI 개선 (업무/개인/공부)
3. 진행률 대시보드, 더블 클릭 수정
4. 다크 모드, 완료 항목 일괄 삭제, 단축키
5. 정렬 옵션, 오늘의 격언, JSON 내보내기/가져오기

사용한 명령어: `/init`(CLAUDE.md 생성), `/status`(상태 확인), `/model`(모델 선택), `/help`(명령어 목록)

### 5주차 · 작업 재개와 자동 카테고리 분류
```bash
claude --resume        # 이전 대화 목록에서 골라 이어서 작업 (최근 대화는 claude -c)
```
```
현재 할 일 관리 앱에 키워드 기반 자동 카테고리 분류 기능을 추가해 줘.
```
- `Shift + Tab` 으로 자동 승인 모드 전환
- `/context` 로 컨텍스트 사용량 확인, `/compact` 로 대화 요약·압축

### 6주차 · 캡처 이미지로 데스크톱 UI 개선
앱 화면을 캡처해 `화면캡처.png`로 저장하고 Claude Code 창에 끌어 놓은 뒤 요청했습니다.
```
[Image #1] 현재 디자인은 모바일에 최적화되어 있는 것 같아. 데스크톱 환경에서도 전체 화면에서 UI를 볼 수 있도록 디자인을 수정해 줘. 수정한 디자인은 'web_version'이라는 새로운 폴더를 생성한 뒤, 그곳에 저장해 줘.
```
`@` 참조로 점검
```
@script.js 파일에서 다크 모드 관련 함수를 찾고 설명해 줘.
@web_version 폴더에 있는 파일들을 분석해서 할 일 관리 앱이 데스크톱 환경에 최적화되었는지 확인해 줘.
```
- `/config` 설정 확인, `/doctor` 환경 진단, `/export` → `todo-app-conversation.txt` 로 대화 저장

> 위 프롬프트는 실습 당시 그대로입니다. 제출 전 정리하면서 `web_version/`은 `week06/`으로, 5주차 화면은 `week05/`로 옮겼고, 두 화면이 복사해 쓰던 `script.js`는 공통 `core.js`와 화면별 `ui.js`로 나눴습니다.
